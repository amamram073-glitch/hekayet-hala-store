# CyberShield OS

منصة أمن سيبراني متعددة المؤسسات لمتابعة الأصول التي أُضيفت وفُوّضت صراحةً فقط. هذا المشروع **نسخة MVP قابلة للاستكمال**؛ ليس اعتماداً أو شهادة أمنية، ولا ينبغي اعتبار نجاح الاختبارات بديلاً عن مراجعة أمنية مستقلة قبل تخزين بيانات إنتاجية حساسة.

## موقع المشروع

المشروع مستقل في `cybershield-os/` داخل مستودع متجر Hekayet Hala. لا يستبدل المتجر أو ملفاته، ويحتوي على تطبيق ويب وخلفية وخدمات تشغيل خاصة به.

## البنية

- `apps/web`: React وTypeScript وVite، واجهة عربية افتراضية مع RTL وتبديل الإنجليزية/LTR.
- `apps/api/app`: FastAPI وPydantic وSQLAlchemy 2، وثائق OpenAPI عند `/docs`.
- `apps/api/alembic`: ترحيلات PostgreSQL.
- `services/worker`: مهام Celery لمعالجة الأحداث والفحوص الآمنة والسياسات الدورية.
- `infrastructure/nginx`: تمرير موحد إلى واجهة ثابتة وAPI وWebSocket.
- `tests`: اختبارات API وتدفقات العزل والتفويض.
- `docker-compose.yml`: PostgreSQL وRedis وAPI وواجهة Nginx ثابتة وعامل Celery وCelery Beat.

## القدرات الموجودة

- عضويات مؤسسية وأدوار، جلسات قابلة للإبطال، إدارة فريق ودعوات، تسجيل تدقيقي.
- أصول تبدأ غير مفوّضة؛ لا يُقبل الفحص إلا بعد تصريح صريح من المستخدم المخول. الفحص محدود بـ DNS/TLS وطلب HTTPS واحد، ويمنع عناوين الشبكات الداخلية والتحويلات وDNS rebinding؛ لا توجد أدوات استغلال أو فحص منافذ أو مسح عشوائي.
- إدخال أحداث SIEM عبر مفاتيح API خاصة بالمؤسسة، تُخزّن بصماتها فقط، مع تدوير/إبطال وحد لكل مفتاح، وقواعد كشف منظمة لا تقبل الشيفرة.
- تنبيهات مع أدلة وروابط أحداث، مؤشرات تهديد تُدار محلياً، قواعد كشف، موجز SOC، مؤشرات MTTD/MTTR والإيجابيات الكاذبة والمعالجة عندما تتوفر عينات حقيقية، واتجاه تاريخي للدرجة والمخاطر.
- تحقيقات وقضايا وروابط موارد وملاحظات ومهام وتحميل أدلة مع SHA-256 وتخزين خارج web root.
- طلبات موافقة: يمكن لمدير مختلف اعتماد الإجراءات الداخلية المدعومة (إنشاء مهمة، تغيير حالة تنبيه، إنشاء حادث). أنواع المراجعة الأخرى تسجّل القرار فقط. **لا** تنفذ هذه النسخة أوامر shell أو حجب حساب/جهاز أو إجراءات خارجية تلقائية.
- إشعارات داخل التطبيق وWebSocket مع حصر وصول المستخدم بمؤسسته ومستلمه. Webhook اختياري عبر outbox وتوقيع HMAC وتشفير السر وDNS/IP pinning وحد محاولات؛ لا تُرسل البيانات لمزود خارجي ما لم ينشئ المسؤول وجهة ويختار أنواع أحداثها.
- لوحة صحة داخلية محمية بدور المدير عند `/api/system/health`، تشمل قاعدة البيانات وRedis والعامل ووسيط WebSocket.
- سجل بحث عام مضبوط النطاق، ترقيم/ترشيح الأحداث والتنبيهات والتدقيق، تقارير مشتقة من السجلات، وAI Analyst اختياري عند توفير مزود وإعداداته.
- سياسة احتفاظ اختيارية ومطفأة افتراضياً. لا تُحذف أحداث مرتبطة بدليل تنبيه/تحقيق عبر مهمة الاحتفاظ الآلية. سجلات التدقيق ليست ضمن الحذف الآلي.
- عقود مزودين قابلة للتوسعة في `apps/api/app/services/providers.py`، دون تمكين أي تكامل خارجي مسبقاً.

**البيانات التجريبية** ليست جزءاً من قاعدة الإنتاج، وبيانات seed الاختيارية معلّمة بوضوح، ولا تفوض أي أصل للفحص.

## تطوير محلي

المتطلبات: Python 3.12، Node 22، Redis، وPostgreSQL (أو SQLite للاختبارات والتطوير). من مجلد `cybershield-os`:

```bash
cp .env.example .env
# للتطوير المحلي: DATABASE_URL=sqlite:///./cybershield-dev.db
# REDIS_URL=redis://localhost:6379/0
# APP_URL=http://localhost:5173
# ENVIRONMENT=development
# COOKIE_SECURE=false
python3 -m venv .venv
. .venv/bin/activate
pip install -r apps/api/requirements.txt
cd apps/web && npm ci && cd ../..
```

شغّل API من `apps/api`:

```bash
cd apps/api
PYTHONPATH=.:../.. uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

ومن نافذتين أخريين عند جذر المشروع: العامل `PYTHONPATH=apps/api:. .venv/bin/celery -A services.worker.celery_app.celery_app worker --loglevel=INFO`، والواجهة `cd apps/web && npm run dev`. افتح `http://localhost:5173`. يلزم Redis والعامل لمعالجة الأحداث والفحوص.

## النشر الدائم على خادم خارجي تملكه

هذا الإعداد يشغّل التطبيق على الخادم الذي تديره؛ **لم يُنشر التطبيق بعد إلى خادم خارجي في هذه الجلسة** لأن لا خادم متصلاً أو عنوان/طريقة وصول متاحة حالياً. لا ترسل كلمة مرور SSH أو مفتاحاً خاصاً في المحادثة. بعد توصيل الخادم وتوفير قناة نشر مصرح بها:

1. جهّز خادماً مدعوماً بـ Docker Engine وDocker Compose، واسم نطاق وشهادة TLS في وكيل عكسي على المضيف (Nginx/Caddy/مزود مكافئ). حدّث النظام، حدّ الوصول الإداري، وافتح 80/443 فقط للعموم.
2. انسخ المجلد `cybershield-os/` إلى مسار ثابت على الخادم، ثم أنشئ `.env` محلياً للخادم (`chmod 600 .env`). لا تضع الملف في Git أو في واجهة الويب.
3. ولّد أسراراً قوية وفريدة: `POSTGRES_PASSWORD` و`REDIS_PASSWORD` (يفضل hex لتجنّب الترميز)، و`JWT_SECRET` (`openssl rand -hex 32`) ومفتاح Fernet لـ`WEBHOOK_ENCRYPTION_KEY` (`python3 -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'`). لا تستخدم القيم النموذجية أو الافتراضية.
4. عيّن `APP_URL=https://اسم-النطاق` و`ENVIRONMENT=production` و`COOKIE_SECURE=true` و`ALLOW_PUBLIC_REGISTRATION=false`، واجعل `HTTP_PORT=127.0.0.1:8080` كيلا تُعرّض منفذ التطبيق مباشرة للإنترنت. اضبط الوكيل العكسي لتمرير WebSocket مع Upgrade headers إلى `/api/ws/events` وحدد حدوداً مناسبة لأحجام الطلب والمهلات.
5. ابدأ قاعدة البيانات وRedis، ثم طبّق migration **قبل** تشغيل التطبيق بالإصدار الجديد:

   ```bash
   docker compose up -d postgres redis
   docker compose run --rm --no-deps api sh -c 'cd /workspace/apps/api && alembic upgrade head'
   docker compose up -d --build
   docker compose ps
   curl -fsS http://127.0.0.1:8080/api/health
   ```

6. أنشئ المالك الأول بشكل تفاعلي (كلمة المرور لا تُمرر في سطر الأوامر):

   ```bash
   docker compose run --rm -it --no-deps api python /workspace/apps/api/bootstrap_owner.py
   ```

   بعد ذلك ادخل عبر HTTPS، أنشئ دعوات لأعضاء المؤسسة، وأبقِ `ALLOW_PUBLIC_REGISTRATION=false`. يمكن ضبط `APP_URL` ومضيف TLS أولاً؛ لا تستخدم `COOKIE_SECURE=false` على الإنترنت.
7. راجع `/docs` من نطاق داخلي أو قيّد الوصول إليها في الوكيل، وتحقق من `/api/system/health` بحساب مدير. اختبر TLS، التسجيل التدقيقي، ونسخة الاستعادة في قاعدة مؤقتة قبل وضع بيانات فعلية.

لا يضم Compose شهادة TLS بذاته. يلزم وكيل TLS موثوق على المضيف، وتحديثات دورية للصور، جدار شبكة، ومراقبة موارد القرص والذاكرة وRedis وPostgreSQL. لا تُعرض منافذ PostgreSQL أو Redis أو API للعامة.

## الترحيلات والاختبارات

```bash
cd apps/api
PYTHONPATH=.:../.. alembic upgrade head
PYTHONPATH=.:../.. alembic current
cd ../..
.venv/bin/pytest -q
```

ينشئ التطبيق الجداول تلقائياً في `development` فقط؛ في `production` يجب تشغيل Alembic صراحةً. يستخدم الاختبار SQLite ولا يحتاج إلى شبكة. راجع نتائج الاختبارات التي أُجريت لهذا الإصدار قبل النشر.

## النسخ الاحتياطي والاستعادة

`./scripts/backup.sh` ينشئ dump بصيغة PostgreSQL custom ونسخة tar.gz لمجلد الأدلة، ثم يتحقق من dump/gzip ويكتب SHA-256 بصلاحيات ملفات مقيدة. خُصّص لبيئة Docker Compose؛ لا يرسل النسخ إلى مكان خارجي ولا يشفرها تلقائياً. احفظها خارج الخادم في تخزين مشفّر ومقيّد الوصول، واختبر سلامة checksum واستعادة دورية في بيئة منفصلة.

مثال جدولة يومية يدوية على المضيف (غيّر المسارات والحساب وفق إعدادك):

```cron
17 2 * * * cd /srv/cybershield-os && BACKUP_DIR=/srv/private-backups/cybershield ./scripts/backup.sh >> /var/log/cybershield-backup.log 2>&1
```

للاستعادة، أوقف الكتابات واحتفظ بنسخة حديثة من قاعدة الإنتاج أولاً؛ ثم استخدم `scripts/restore-db.sh <dump> --confirm-overwrite` بعد مراجعة الملف. السكربت يستبدل كائنات قاعدة البيانات ولا يستعيد ملفات الأدلة تلقائياً؛ استرجع أرشيف الأدلة إلى staging، تحقق من checksum ومساراته، ثم أعده إلى volume في نافذة صيانة. لا تستخدم dump غير موثوق.

## إعدادات وتشغيل

- راجع `.env.example`. مفتاح AI اختياري، ومفتاح تشفير Webhook لازم إذا أنشأت وجهات Webhook؛ SMTP موجود كإعداد مستقبلي لكن إرسال البريد غير مفعّل.
- في الإنتاج تُطبّق حدود الطلبات عبر Redis، مع حد إدخال مستقل لكل API key. فشل rate limiter يمنع الكتابات ويعيد `503` بدلاً من تخطي الحماية.
- كل قارئ/كاتب مورد يقيّد استعلامه بمؤسسة الجلسة أو API key. لا تُرسل `organization_id` موثوقاً من العميل.
- معلومات الامتثال تظهر `NOT_ASSESSED` حتى يُبنى تقييم إطار ضوابط حقيقي. قيمة الصفر لا تعني امتثالاً أو عدم امتثال.
- Playbooks مخزنة بهيكل خطوات معروف ومحدود؛ تشغيلها الآلي/المجدول ليس مفعّلاً. إجراءات الموافقة المدعومة داخلية فقط.

## حدود معروفة يجب أخذها بالحسبان

لا توجد مصادقة متعددة العوامل أو استعادة كلمة مرور/تحقق بريد؛ لا توجد صفحة SUPER_ADMIN أو فوترة؛ لا توجد موصلات جاهزة لموردي Cloud/SIEM/TI أو Slack/Teams أو أنظمة التذاكر؛ لا توجد رسائل بريد؛ ولا يوجد تقييم NIST/ISO/SOC 2 أو تشغيل تلقائي للـ playbooks. Webhook عام اختياري فقط. لا توجد اختبارات Playwright/E2E للواجهة، أو مراجعة اختراق مستقلة، أو تحقق Docker على خادم الإنتاج في هذه الجلسة. ينبغي اعتبار مؤشرات MTTD/MTTR غير متاحة عند عدم وجود عينات، واستخدام بيانات ومراقبة فعلية بعد النشر. الفحص المحدود ليس ماسح ثغرات شاملاً. لا توجد خدمة نسخ احتياطي خارجية أو تشفير تلقائي للنسخ في المنتج.

## الاستخدام المسؤول

لا تسجّل أو تفحص إلا الأنظمة التي تملكها مؤسستك أو لديك تفويض مكتوب صريح لها. انظر `SECURITY.md` و`docs/security-model.md` قبل الاستخدام. إقرار المستخدم داخل المنصة لا يثبت الملكية قانونياً.
