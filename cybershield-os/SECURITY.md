# Security Policy

## الاستخدام المصرح به فقط

- لا تضف أو تفحص سوى الأنظمة التي تملكها مؤسستك أو لديك تفويض صريح مكتوب لاختبارها.
- سجّل الأصل في حساب المؤسسة، ثم أكّد التفويض ببيان يوضح أساس الصلاحية قبل بدء التقييم.
- أوقف التفويض فور انتهائه أو عند طلب المالك ذلك.
- إقرار التفويض داخل التطبيق لا يتحقق مستقلاً من ملكية النطاق ولا يحل محل موافقات قانونية أو تعاقدية لازمة.

## سلوك الفحص

يُسمح فقط بملاحظات منخفضة الأثر: استعلام DNS أساسي، تحقق TLS، وطلب HTTPS HEAD محدود لاستخراج ترويسات الأمان. يتحقق العامل من DNS العام ويرفض العناوين المحلية/المحجوزة ويربط الاتصال بعنوان محقق، ويعطل التحويلات. لا يتضمن المشروع استغلالاً أو تخمين بيانات اعتماد أو سرقة بيانات أو برمجيات خبيثة أو إخفاء/استمرارية أو فحص منافذ أو طلبات تدميرية.

## إعداد آمن

- لا تستخدم الأسرار الافتراضية أو `COOKIE_SECURE=false` خارج بيئة التطوير المحلية.
- ضع التطبيق خلف HTTPS، واحفظ `.env` ومفاتيح AI/SMTP خارج المستودع.
- لا تفتح PostgreSQL أو Redis للإنترنت العام. قيّد الاتصالات الصادرة للعامل بقواعد شبكة مناسبة.
- راجع صلاحيات المؤسسة والنسخ الاحتياطية وسجلات التدقيق قبل تقديم الخدمة لعملاء.

## الإبلاغ عن ثغرة

لا تختبر نطاقاً حقيقياً من خلال هذا المشروع إلا بعد تفويض. أبلغ مالك المستودع بوسيلة خاصة، وقدّم خطوات إعادة إنتاج غير مدمرة ونسخة/إصدار متأثر. لا تنشر بيانات العملاء أو الأسرار.

## الحالة

المشروع MVP قيد التطوير، ولم يخضع لمراجعة مستقلة أو اختبار اختراق. لا يُستخدم بديلاً عن عملية إدارة مخاطر أمنية مكتملة.
